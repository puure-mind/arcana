# Задача: создать docs/design-guidelines.md для Arcana

## Контекст проекта

Arcana — слот-игра на основе карт Таро.

Технологии:
- Next.js, React, TypeScript
- PixiJS — игровое поле и графические элементы
- GSAP — анимации
- Tailwind CSS — интерфейс
- AssetPack — подготовка и управление графическими ресурсами

Игровая механика описана в `docs/game-rules.md`. Математическая модель и результаты игры формируются отдельно через Stake Math SDK.

## Источник истины

Основной источник визуальных требований — существующие макеты Figma, доступные через подключённый Figma MCP.

Перед созданием документа:

1. Найди в Figma макеты проекта Arcana.
2. Изучи все релевантные страницы, фреймы, компоненты и варианты состояний.
3. Получи доступные через MCP дизайн-токены, стили, размеры, изображения и метаданные.
4. Изучи существующие файлы проекта и правила из `AGENTS.md`.
5. Сопоставь макеты с игровыми сценариями из `docs/game-rules.md`.

Не придумывай цвета, размеры, шрифты, состояния или анимации, которых нет в источниках.

Если Figma MCP не позволяет найти проект автоматически, запроси ссылку на файл или конкретные фреймы.

## Содержание docs/design-guidelines.md

### 1. Design Sources
- Ссылки на Figma-файл и ключевые фреймы.
- Назначение каждого экрана.
- Статус макетов: утверждённый, черновой или неизвестный.

### 2. Visual Identity
- Художественное направление, представленное в макетах.
- Фон, декоративные элементы, текстуры.
- Правила визуальной иерархии.

### 3. Design Tokens
- Цвета и их назначение.
- Типографика.
- Отступы и размеры.
- Скругления, границы, тени и эффекты.

Указывай точные значения из Figma, когда они доступны. По возможности используй существующие переменные и стили Figma.

### 4. Game Layout
- Структура игрового экрана.
- Размеры и расположение поля 5×4.
- Панели баланса, ставки и выигрыша.
- Кнопка Spin и дополнительные элементы управления.
- Поведение интерфейса при изменении размеров экрана.

### 5. Tarot Cards
- Пропорции и размеры карт.
- Иллюстрации и рамки.
- Обычные и специальные символы.
- Состояния карты: обычная, выигрышная, выделенная, неактивная.
- Требования к качеству и масштабированию ассетов.

### 6. Game States
Опиши визуальное представление состояний, если они присутствуют в Figma:

- Idle
- Spinning
- Win Presentation
- Free Spins
- Risk All
- The Prophecy
- Loading
- Error

Для отсутствующих состояний создай список открытых вопросов. Не проектируй их самостоятельно.

### 7. Animation Guidelines
- Анимации вращения и остановки поля.
- Подсветка выигрышных кластеров.
- Отображение локальных множителей.
- Переходы между игровыми режимами.
- Анимации Risk All и Free Spins.

Указывай длительности, easing и последовательности только при наличии подтверждённых данных. Статичные макеты не считай доказательством конкретной анимации.

### 8. Responsive Design
- Поддерживаемые размеры экранов.
- Компоновка для desktop и mobile.
- Правила масштабирования PixiJS.
- Минимальные размеры интерактивных элементов.
- Ограничения по переполнению и обрезке.

Не выводи произвольные breakpoint-значения из одного макета.

### 9. Implementation Guidelines
- Какие элементы реализуются через React/Tailwind CSS.
- Какие элементы относятся к PixiJS.
- Какие анимации выполняются через GSAP.
- Как организовать ассеты через AssetPack.
- Как избежать дублирования дизайн-токенов.

Не меняй архитектуру проекта без необходимости.

### 10. Missing Designs & Open Questions

## Требования к результату

Создай реальный файл `docs/design-guidelines.md` в репозитории.

Для каждого существенного визуального решения указывай источник: Figma-фрейм, компонент, переменную или существующий файл проекта.

Разделяй:
- **Confirmed** — подтверждено макетом или токеном.
- **Inferred** — предположение на основе нескольких макетов.
- **Missing** — отсутствует в источниках.

Не подменяй отсутствующий дизайн собственной реализацией.

Документ должен быть понятен разработчику и ИИ-агенту, который будет реализовывать интерфейс.

## Проверка результата

Перед завершением:
1. Проверь соответствие документа макетам Figma.
2. Убедись, что не добавлены неподтверждённые значения.
3. Проверь согласованность с `docs/game-rules.md`.
4. Проверь корректность ссылок на Figma.
5. Выведи список отсутствующих состояний и открытых вопросов.

В ответе укажи созданный файл, использованные Figma-источники и ограничения анализа.
